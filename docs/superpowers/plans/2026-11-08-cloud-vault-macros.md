# 云宝库导入宏制作计划

**目标：** 为 Minecraft 26.3 的现有 Litemacro 制作普通、不祥两份可导入 JSON，不修改 mod 源码。

**方案：** 单分支顺序执行，按菜单物品识别入口、选择页和领奖页。兑换点击后直接等待领奖，禁止重发兑换；使用有限的点击查找和关闭检查，避免无期限等待及 Repeat 计数跨轮残留。

**工具：** Litemacro v1 JSON、现有 Java MacroModel 加载器、Node.js 场景模拟。

## 约束

- 普通宝库检查 minecraft:trial_key，不祥宝库检查 minecraft:ominous_trial_key。
- 全部菜单点击为普通左键，检查节点不自动点击。
- 优先处理已有奖励，动画及领奖阶段不要求剩余钥匙。
- 默认循环到钥匙耗尽，关闭自动启动、常驻运行及随机延迟。
- 不修改源码，不提交、不推送、不替用户写入游戏配置或 Downloads。
- 未识别菜单只有限等待领奖；超时保留菜单并停止。
- 聊天只用于失败诊断，不作为下一轮的触发条件。
