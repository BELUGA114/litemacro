# 云宝库导入宏

适用于本仓库 Minecraft 26.3 版现有 Litemacro，不需要修改 mod。

- `cloud-vault-normal.json`：普通宝库，消耗 `minecraft:trial_key`。
- `cloud-vault-ominous.json`：不祥宝库，消耗 `minecraft:ominous_trial_key`。

## 导入与运行

1. 将所需 JSON 复制到运行 Minecraft 的 Windows 用户的 `Downloads` 文件夹根目录。导入界面会显示实际扫描路径。
2. 游戏内按 `B` 打开 Litemacro，选一个空宏槽，点击 `Import`，选择对应文件。导入会覆盖所选宏槽。
3. 初次运行只准备一把对应钥匙。手动启动，确认进入正确宝库、完成抽奖并自动领取奖励。
4. 验证后再放入更多钥匙。默认持续循环，直到钥匙耗尽或遇到异常。
5. 停止时使用宏界面的 `Stop` 或 `/litemacro stop`。普通、不祥两份宏不要同时运行。

## 行为

已开菜单会先检查领奖按钮，再检查宝库选择按钮和云宝库入口。未识别的菜单只有限等待领奖，不发出兑换点击；没有容器菜单时检查钥匙，然后潜行、等待 300 ms、按 F、取消潜行并寻找入口。已有待领奖奖励和正在抽奖的流程不会被剩余钥匙为零打断。

发出宝库选择点击后，宏只查找 `minecraft:lime_concrete 点击领取全部奖励`，不再次兑换。领奖查找有六段，每段约五秒客户端 tick 时间，共约三十秒。找到后只点击一次，再最多检查十六次菜单关闭，每次间隔 250 ms。菜单关闭后等待 750 ms，重新开始下一轮。

缺钥匙、菜单打不开、目标缺失、抽奖超时或领奖后不关闭都会停止。异常时保留菜单，供手动检查；不会主动关闭未领奖页面。服务器缺钥匙聊天采用 `contains` 匹配，不依赖感叹号是全角还是半角；聊天只用于超时后的诊断，旧提示不会触发新兑换。

## 首次验证与限制

- F 必须仍绑定 Minecraft 的副手交换动作。按键宏需要实际游戏窗口中验证；其他模组及服务器的输入处理可能影响 Shift+F。
- 菜单匹配基于物品 ID 加文本包含匹配，搜索范围包括名称和提示文字。若普通、不祥两个按钮的说明都含对方名称，必须先调整点击过滤条件，不能继续批量运行。
- 本宏没有界面标题、大小或容器身份的严格校验。中途启动遇到未知菜单会等待匹配的领奖按钮；不要运行时手动换菜单、关菜单或取放物品。
- “领奖点击后菜单关闭”是完成依据。人工关菜单及服务器异常关菜单不能完全与正常领奖区分，聊天不是本轮成功的强确认。
- 未自动处理背包容量或溢出奖励，请先确认该服务器背包满时的处理方式。
- 断线后的行为由现有 mod 管理；本宏关闭自动启动与常驻运行，不配置自动重连。
- 文件加载和模拟验证不能代替实服验证。首次一把钥匙验证通过后再批量运行。
