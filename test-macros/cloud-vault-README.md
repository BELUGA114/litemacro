# 云宝库导入宏

适用于 Minecraft 26.3 的 Litemacro 1.0.99 构建。需要安装包含通用数值组件的新 JAR，旧版 JAR 不支持这些 JSON。

- `cloud-vault-normal.json`：普通宝库，消耗 `minecraft:trial_key`。
- `cloud-vault-ominous.json`：不祥宝库，消耗 `minecraft:ominous_trial_key`。

## 导入与运行

1. 将所需 JSON 复制到运行 Minecraft 的 Windows 用户的 `Downloads` 文件夹根目录。导入界面会显示实际扫描路径。
2. 游戏内按 `B` 打开 Litemacro，选一个空宏槽，点击 `Import`，选择对应文件。导入会覆盖所选宏槽。
3. 初次运行只准备一把对应钥匙。手动启动，确认进入正确宝库、完成抽奖并自动领取奖励。
4. 验证后再放入更多钥匙。默认持续循环，直到钥匙耗尽或遇到异常。
5. 停止时使用宏界面的 `Stop` 或 `/litemacro stop`。普通、不祥两份宏不要同时运行。

## 行为

已开菜单会先检查领奖按钮，再检查宝库选择按钮和云宝库入口。未识别的菜单只有限等待领奖，不发出兑换点击；没有容器菜单时检查钥匙，然后潜行、等待 300 ms、按 F、取消潜行并寻找入口。已有待领奖奖励和正在抽奖的流程不会被剩余钥匙为零打断。

发出宝库选择点击后，宏只查找 `minecraft:lime_concrete 点击领取全部奖励`，不再次兑换。领奖查找有六段，每段约五秒客户端 tick 时间，共约三十秒。找到后只点击一次，再最多检查十六次菜单关闭，每次间隔 250 ms。菜单关闭后等待 750 ms，重新开始下一轮。

缺钥匙、菜单打不开、目标缺失、抽奖超时或领奖后不关闭都会停止。异常时保留菜单，供手动检查；不会主动关闭未领奖页面。缺钥匙聊天只用于超时诊断。清理预警由独立的聊天数值组件记录，后续无关消息不会覆盖预警。

## 清理保护

两个 JSON 使用公共数值比较、条件等待、清除数值记录和条件点击组件。mod 不内置服务器清理文本、600 秒周期或恢复策略。

- 新一轮及实际兑换点击都要求计分板剩余大于 30 秒，且聊天预警也允许继续。
- 已兑换的一轮仍可领奖；每次领奖点击都要求计分板和聊天预警剩余大于 10 秒。
- 暂停后先确认计分板降到不超过 30 秒，再等待回到至少 590 秒，清除旧聊天预警，缓冲 5 秒后继续。
- 领奖恢复只返回当前领奖步骤，不再次兑换。按钮缺失时沿用原来的有限等待和停止行为。
- 计分板缺失、数值冲突或数值超过 5 秒不更新都会阻止点击。保护等待没有固定超时，可随时手动停止。

计分板正则位于 `node-70`、`node-75`、`node-77`、`node-82`、`node-85`；聊天正则位于 `node-74`、`node-76`。`node-85` 将服务器声明的上限 600 配置成独立条件，阻止超出范围的数值放行。各节点 `value2` 配置比较规则，例如：

```json
{
  "type": "builder:logic.scoreboardNumber",
  "value": "垃圾清理\\s*[:：]\\s*\\[\\s*(\\d+)\\s*\\]",
  "value2": "op=gt value=30 stale=5 rate=-1 mode=latest missing=false"
}
```

`rate=-1` 根据实际经过的秒数推算剩余时间；恢复判断用 `rate=0`，要求服务器实际更新显示值。聊天用 `mode=min` 保留较早的期限，新周期由 JSON 明确清除。所有选项均须显式配置；完整说明见 [Component Inputs](../wiki/08-component-inputs.md#number-comparison-components-minecraft-263-branch)。

## 首次验证与限制

- F 必须仍绑定 Minecraft 的副手交换动作。按键宏需要实际游戏窗口中验证；其他模组及服务器的输入处理可能影响 Shift+F。
- 菜单匹配基于物品 ID 加文本包含匹配，搜索范围包括名称和提示文字。若普通、不祥两个按钮的说明都含对方名称，必须先调整点击过滤条件，不能继续批量运行。
- 本宏没有界面标题、大小或容器身份的严格校验。中途启动遇到未知菜单会等待匹配的领奖按钮；不要运行时手动换菜单、关菜单或取放物品。
- “领奖点击后菜单关闭”是完成依据。人工关菜单及服务器异常关菜单不能完全与正常领奖区分，聊天不是本轮成功的强确认。
- 未自动处理背包容量或溢出奖励，请先确认该服务器背包满时的处理方式。
- 暂停生产不能保护已经掉在地上、尚未拾取的奖励，需要留出拾取时间并确保背包容量。
- 紧急暂停会保留领奖菜单；未领取奖励是否能跨服务器清理保留，需要实服确认。
- 断线后的行为由现有 mod 管理；本宏关闭自动启动与常驻运行，不配置自动重连。
- 文件加载和模拟验证不能代替实服验证。首次一把钥匙验证通过后再批量运行。
